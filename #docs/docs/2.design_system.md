# 2. Design System

## 2.1 Design direction

CivicLens should feel trustworthy, civic-minded, clear, and modern. Prefer a dark-first interface with restrained teal accents and readable contrast. Avoid excessive gradients, distracting animations, and a trading-terminal aesthetic.

## 2.2 Design principles

1. **Evidence before claims:** show the photo and supporting observations before the AI summary.
2. **Human control:** editing and confirmation are prominent.
3. **Clear status:** each report has a visible lifecycle state.
4. **Accessible by default:** keyboard support, focus indicators, semantic headings, and sufficient contrast.
5. **Mobile-first:** image upload and review must work on narrow screens.
6. **Honest AI:** label mock output and uncertain inferences.

## 2.3 Tokens

Use CSS custom properties in one central token file.

```css
:root {
  color-scheme: dark;
  --color-bg: #0b1114;
  --color-surface: #121b20;
  --color-surface-raised: #18252b;
  --color-border: #2a3a40;
  --color-text: #f3f7f8;
  --color-text-muted: #a8b7bc;
  --color-primary: #43d9c0;
  --color-primary-hover: #70e7d4;
  --color-info: #76baff;
  --color-success: #65d6a6;
  --color-warning: #f2c66d;
  --color-danger: #ff8585;
  --radius-sm: 8px;
  --radius-md: 14px;
  --radius-lg: 20px;
  --space-1: 4px;
  --space-2: 8px;
  --space-3: 12px;
  --space-4: 16px;
  --space-6: 24px;
  --space-8: 32px;
  --content-max: 1200px;
}
```

These are starting tokens. Verify contrast and adjust after implementing components.

## 2.4 Typography

- Use a clean system sans-serif stack.
- Body text: 16px minimum where practical.
- Secondary text: do not rely on low contrast to indicate secondary importance.
- Use short headings and sentence case.
- Avoid long all-caps labels.
- Use tabular numerals for dates or counts where useful.

## 2.5 Layout

- Main content max width: approximately 1200px.
- Desktop dashboard: navigation/sidebar plus main content.
- Mobile: single-column layout and compact navigation.
- Use consistent spacing tokens; do not insert arbitrary margins everywhere.
- Keep report images at a sensible max height and preserve aspect ratio.
- Do not hide key report information behind hover-only interactions.

## 2.6 Core components

- `AppShell`
- `TopBar` / `SideNav`
- `PageHeader`
- `PrimaryButton`, `SecondaryButton`, `IconButton`
- `ImageUploader`
- `ImagePreview`
- `AnalysisStatus`
- `ObservationList`
- `InferenceNotice`
- `PriorityBadge`
- `ReportStatusBadge`
- `ReportCard`
- `ReportTable` or responsive report list
- `FilterBar`
- `EmptyState`
- `ErrorMessage`
- `ConfirmDialog`
- `Toast` or inline feedback

Components should have a single responsibility and explicit props.

## 2.7 Status and priority styles

Color must not be the only way to communicate state; always include text or an icon with accessible text.

Suggested status labels:
- Draft
- Submitted
- Under review
- In progress
- Resolved
- Rejected

Suggested priority labels:
- Low
- Medium
- High
- Unknown

Do not use a high-priority color to imply that an AI assessment is verified. Include a label such as “AI-suggested priority — review required.”

## 2.8 Interaction states

Every interactive component should define:
- Default
- Hover
- Focus-visible
- Active
- Disabled
- Loading, when applicable
- Error, when applicable

Uploads should show accepted file types and maximum size before selection. Analysis should show progress and allow retry after a recoverable error.

## 2.9 Motion

- Use short transitions, usually 120–220ms.
- Do not animate essential content in ways that delay access.
- Respect `prefers-reduced-motion`.
- No perpetual background animation.

## 2.10 Accessibility checklist

- Semantic HTML and logical heading order
- Full keyboard operation
- Visible focus rings
- Labels for all fields
- Alt text for meaningful images; decorative images use empty alt text
- Error messages associated with fields
- Dialog focus management
- Color contrast checked
- Reduced-motion support
- Touch targets large enough for mobile use
