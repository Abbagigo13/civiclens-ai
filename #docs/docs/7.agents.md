# 7. AI Coding Agent Rules

These rules apply when using coding assistants or autonomous agents to implement CivicLens AI.

## 7.1 Project mission

Build a dependable, human-reviewed visual reporting tool. Prioritize the end-to-end MVP over speculative features or flashy but nonfunctional UI.

## 7.2 Source of truth

Read these files before making substantial changes:
1. `README.md`
2. `docs/1.prd.md`
3. `docs/2.design_system.md`
4. `docs/3.code_style.md`
5. `docs/4.architecture.md`
6. `docs/5.security.md`
7. `docs/6.testing.md`

If instructions conflict, security requirements and the PRD's human-review requirements take priority. Ask for clarification if a product decision cannot be safely inferred.

## 7.3 Work in small milestones

Implement in this order:
1. Repository scaffold and configuration
2. FastAPI health endpoint and frontend shell
3. Safe image upload and preview
4. Mock analysis provider and typed response schema
5. Analysis review/edit screen
6. Report persistence and dashboard
7. Status lifecycle
8. Automated tests
9. Real AI provider adapter after access is verified
10. Optional SAM segmentation and visual overlay
11. UI polish and demo preparation

Do not skip directly to optional integrations before the core workflow works.

## 7.4 Required behavior

- Make the smallest coherent change that satisfies the task.
- Inspect existing files before replacing them.
- Do not overwrite working user changes without explaining the impact.
- Provide complete file contents when asked for copy/paste implementation.
- List exact paths for every new or changed file.
- Give PowerShell commands that match Windows when the user is working on Windows.
- Prefer a few clear steps over huge command output.
- Do not claim tests passed unless they were actually run and their output was checked.
- Do not claim a file, endpoint, API, model, or deployment exists until it has been implemented and verified.
- Keep the application functional in mock mode.
- Add or update tests for behavior changes.

## 7.5 Model integration rules

- Verify current official API documentation, model availability, account permissions, and request formats before implementing provider calls.
- Never invent endpoint URLs, SDK methods, model identifiers, or response fields.
- Keep credentials on the backend.
- Use environment variables and document required settings.
- Add timeouts and bounded retries.
- Validate model output with Pydantic before returning it.
- Clearly identify mock output in the UI.
- Do not silently fall back from a failed real provider to fabricated output; if fallback is offered, label it explicitly.
- Treat model output as untrusted and potentially incorrect.

## 7.6 Safety and privacy rules

- Do not implement face recognition or identify people in uploaded photos.
- Do not infer sensitive personal traits, intent, or criminality.
- Do not expose EXIF GPS metadata unintentionally.
- Do not make unsupported claims about issue severity, exact measurements, or official resolution.
- Require user review before saving a final report.
- Do not add public posting, background location, or external integrations without explicit product approval.

## 7.7 Coding constraints

- Keep API routes thin.
- Put business logic in services and persistence in repositories.
- Avoid duplicated validation.
- Use typed schemas at boundaries.
- Keep provider-specific code behind an interface.
- Use design tokens rather than hard-coded one-off colors.
- Ensure interactive controls have labels, keyboard focus, and visible states.
- Do not add a dependency unless needed; explain why it is needed.

## 7.8 Agent response format

After completing a coding task, report:
1. What changed
2. Files created or modified
3. Commands to run
4. Tests run and their actual result
5. Known limitations or next step

If blocked, explain the exact blocker and offer the smallest practical next action. Do not hide errors or fabricate successful results.

## 7.9 Definition of success

A coding session succeeds when the requested feature works, the change is understandable, relevant tests pass or outstanding tests are explicitly listed, and no new security or privacy issue has been introduced.
